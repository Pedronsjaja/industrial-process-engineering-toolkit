# Technical reports

Use for an engineering decision, inspection, maintenance record, commissioning, failure analysis, validation, prototype review, progress report or technical recommendation. Choose the closest guide rather than creating a new report type for every task.

## Recommended structure
Document identification → Revision → Responsible team → Scope → Objective → Background → System/equipment description → Methodology → Measurements/evidence → Findings → Technical analysis → Risks/limitations → Recommendations → Actions → Verification criteria → Conclusion → Attachments → Revision history.

Copy the [technical template](../templates/technical-report-template.md). Add a [test record](../templates/test-report-template.md) for commissioning/validation/prototype testing, or [analysis record](../templates/engineering-analysis-template.md) for failure analysis/design comparisons.

| Situation | Guide | Main decision |
|---|---|---|
| Inspection | [Inspection report](inspection-report.md) | What was observed and what review/action is needed? |
| Maintenance | [Maintenance report](maintenance-report.md) | What changed and what verification supports release? |
| Test / commissioning / validation | [Test report](test-report.md) | Did evidence meet the predeclared criteria? |
| Structural/thermal/fluid/mechanism/design analysis | [Engineering analysis](engineering-analysis-report.md) | Which conclusion is supported within the model limits? |
| Progress / recommendation | Technical template | What is completed, pending and recommended, with evidence? |

Use inventory IDs, action/risk references and revision records as described in [Reports](../README.md). Reports are written/reviewed manually; neither a calculated KPI nor a filename grants approval.
