# Test report

Use for a test, experiment, commissioning check or validation record. Copy the [test template](../templates/test-report-template.md).

## Before testing
Record test ID, date, objective, requirement/acceptance criterion, equipment IDs/configurations, setup, instrumentation and calibration status where relevant. Describe environmental conditions that affect the result.
Specify procedure, repeats, data acquisition, units, tolerances, uncertainty treatment and how deviations will be handled. Define pass/fail criteria before seeing results.

## During and after
Preserve raw data and timestamp/context; record deviations and instrument or acquisition failures. Identify processing software/version and calculations. Compare each result with its own criterion; report PASS, FAIL, INCONCLUSIVE or NOT_TESTED with the reason.
Absence of data cannot be a pass. Simulation evidence must remain labeled SIMULATED, separate from physical tests.

Link datasets and [inventory IDs](../../inventory/README.md), capture findings in [5W2H](../../process-management/5w2h/README.md) where needed, and register the reviewed report through [document control](../../document-control/README.md).
See [data practices](../README.md#data-and-results). The toolkit does not execute tests or generate these reports automatically.
