# Methodology

## Improvement chain

**Problem → Evidence → Risk → Action → Owner → Deadline → Indicator → Verification → Standardization → Continuous Improvement**

State the problem using observable evidence, assess risk with locally agreed criteria, assign accountable owners and deadlines, and define how effectiveness will be verified. Retain evidence and update standards only after appropriate review.

## 5S

Seiri (Sort), Seiton (Set in order), Seiso (Shine), Seiketsu (Standardize), and Shitsuke (Sustain) are organizational practices. The current report accepts numeric scores from 0 through 5 inclusive. Define local observable criteria for each level before comparing areas or periods. The meaning is locally defined; the accepted numeric range is fixed in code. A numeric score is a prompt for discussion, not proof of operational excellence.

## PDCA and 5W2H

PDCA structures learning through Plan, Do, Check, and Act. 5W2H makes actions explicit: What, Why, Where, When, Who, How, and How much. Each action should trace to a problem, audit finding, or other documented source.

## FMEA

The tool accepts integer Severity, Occurrence, and Detection ratings from 1 through 10 and calculates RPN as their product. These numeric bounds are fixed in code. Organizations must establish definitions for each level based on process, product, user, and regulatory context. This is a prioritization aid only; RPN alone does not replace risk review or action on severe hazards.

## OEE

OEE is commonly derived from Availability × Performance × Quality. This repository does not yet implement an OEE calculator. Define planned production time, ideal cycle time, and good units consistently before comparing OEE values.
