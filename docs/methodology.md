# Methodology

## Improvement chain

**Problem → Evidence → Risk → Action → Owner → Deadline → Indicator → Verification → Standardization → Continuous Improvement**

State the problem using observable evidence, assess risk with locally agreed criteria, assign accountable owners and deadlines, and define how effectiveness will be verified. Retain evidence and update standards only after appropriate review.

## 5S

Seiri (Sort), Seiton (Set in order), Seiso (Shine), Seiketsu (Standardize), and Shitsuke (Sustain) are organizational practices. Define observable criteria and a consistent rating scale before comparing areas or periods. A numeric score is a prompt for discussion, not proof of operational excellence.

## PDCA and 5W2H

PDCA structures learning through Plan, Do, Check, and Act. 5W2H makes actions explicit: What, Why, Where, When, Who, How, and How much. Each action should trace to a problem, audit finding, or other documented source.

## FMEA

The tool calculates RPN as Severity × Occurrence × Detection for 1-10 inputs. This is a prioritization aid only. Organizations must establish definitions for each scale based on process, product, user, and regulatory context. RPN alone does not replace risk review or action on severe hazards.

## OEE

OEE is commonly derived from Availability × Performance × Quality. This repository does not yet implement an OEE calculator. Define planned production time, ideal cycle time, and good units consistently before comparing OEE values.
