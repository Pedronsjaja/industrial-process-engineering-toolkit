# Common workflows

Choose the smallest route that answers your question. Arrows mean manual handoffs unless the script is named. Run the commands in the linked module guides from the repository root.

| Workflow / when to use | Flow | Files involved | Scripts | Expected result |
|---|---|---|---|---|
| A — Corrective action from 5S: organization finding | 5S finding → 5W2H → KPI → PDCA verification → final report | [Audit template](../quality/5s/5s-audit-template.csv), [action template](../examples/5s-workshop-case/fivew2h-template.csv), [PDCA](../examples/5s-workshop-case/pdca-template.csv), [technical report](../reports/templates/technical-report-template.md) | generate_5s_report.py; generate_kpis.py | Baseline scores, owned action and evidence-based effectiveness conclusion; see [tutorial](tutorials/first-improvement-cycle.md) |
| B — Engineering risk: design/process concern | FMEA → prioritized review → action → verification → technical report | [FMEA template](../quality/fmea/fmea-template.csv), action template above, [analysis template](../reports/templates/engineering-analysis-template.md) | calculate_fmea.py; generate_kpis.py if a snapshot helps | Ranked discussion inputs and a reviewed response, not automatic risk acceptance |
| C — Tool/equipment control: assets or inspection dates unclear | Inventory → validation → inspection review → KPI | [Inventory template](../inventory/templates/inventory-template.csv), [inspection report](../reports/technical/inspection-report.md) | validate_inventory.py; generate_kpis.py | Record-quality findings and status-based ratio; inspection/release decision remains manual |
| D — Engineering project organization: new/shared project | Project structure → naming → revision control → drive governance | [Folder layout](../drive-governance/folder-structure.md), [naming](../document-control/naming-standard.md), [register](../document-control/document-register.csv), [permissions](../drive-governance/permissions.md) | generate_project_structure.py; check_file_names.py | Local folders and naming findings; no cloud permissions or approvals configured |
| E — Test and validation: evaluate a hypothesis or requirement | Setup → raw data → results → analysis → test report → action if needed | [Test template](../reports/templates/test-report-template.md), [analysis guide](../reports/technical/engineering-analysis-report.md), original dataset and requirement reference | No test execution or report generator; check_file_names.py can check released filenames | Traceable test record, criteria comparison and limitations; inconclusive is a valid outcome |

See [module connections](module-workflow.md), [report selection](../reports/README.md) and [evidence practices](../reports/README.md#data-and-results).
