# Terminology

| Term | Meaning in this toolkit |
|---|---|
| 5S | Workplace organization practice: Sort, Set in order, Shine, Standardize, Sustain. |
| Seiri | Sort: distinguish needed items from unnecessary items. |
| Seiton | Set in order: define accessible, identifiable storage locations. |
| Seiso | Shine: clean and observe workplace/equipment condition. |
| Seiketsu | Standardize: establish consistent ways to maintain the first three practices. |
| Shitsuke | Sustain: maintain agreed practices through participation and follow-up. |
| PDCA | Plan, Do, Check, Act: plan a change, try it, evaluate evidence, then adapt or standardize. |
| 5W2H | What, Why, Where, When, Who, How, How much: a structure for actionable plans. |
| FMEA | Failure Modes and Effects Analysis: examine failures, effects, causes, and controls to prioritize action. |
| Severity | Rating of the seriousness of a failure's effect under locally defined criteria. |
| Occurrence | Rating of how likely or frequent a failure cause is under locally defined criteria. |
| Detection | Rating of the difficulty of detecting a failure/cause before its effect; higher commonly means weaker detection. Define local criteria explicitly. |
| RPN | Risk Priority Number: Severity × Occurrence × Detection in this implementation; not a complete risk decision. |
| KPI | Key Performance Indicator: a defined measure interpreted with scope, time, units, and data quality. |
| OEE | Overall Equipment Effectiveness: availability × performance × quality; not calculated by this toolkit. Inventory Availability is a different measure. |
| Nonconformity | Failure to meet a stated requirement or agreed criterion; cite the criterion and evidence. |
| Corrective action | Action addressing the cause of a nonconformity to prevent recurrence; verify effectiveness. |
| Action | An assigned response to a finding or improvement opportunity. |
| Due date | Agreed completion deadline; an open action is overdue here only when its nonblank date precedes the reference date. |
| Evidence | An observation, measurement, record, or reference supporting a claim. |
| Traceability | Ability to follow a result or decision back to identified sources, methods, records, and revisions. |
| Document revision | Identified version of a document with recorded changes and review status. |
| Technical report | Structured record of scope, evidence, analysis, findings, recommendations, and limits. |
| Test report | Record connecting a test procedure and setup to raw data, results, acceptance criteria, and conclusions. |
| Engineering analysis | Reasoned evaluation using assumptions, inputs, methods/models, verification, and interpretation. |

Use domain-appropriate criteria and cite their source. Code fixes FMEA ratings at integers 1–10 and 5S scores at 0–5; it does not supply a validated rating rubric.

For method context, see ASQ's [5S overview](https://asq.org/quality-resources/five-s-tutorial), [FMEA overview](https://asq.org/quality-resources/fmea), and [PDCA overview](https://asq.org/quality-resources/pdca-cycle). These references explain methods; they do not validate this fictional case or certify the software.
